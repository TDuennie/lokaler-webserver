LOKALER WEBSERVER
=================

Zeigt die Dateien aus dem Ordner "www" im Browser an - HTML, CSS,
Bilder, PDF, Video, und PHP mit SQLite.

Alles laeuft auf dem eigenen Rechner. Es geht nichts ins Internet.
Der Ordner darf verschoben, kopiert oder im Drive abgelegt werden -
der Server findet sich immer selbst.


Eine bebilderte Anleitung mit Bildschirmfotos steht in "Anleitung.html" -
einfach doppelklicken. Der Text hier ist die Kurzfassung.


STARTEN
-------

  Doppelklick auf   "Webserver starten.vbs"

Der Browser oeffnet sich von selbst.

Klappt etwas nicht, stattdessen "Webserver mit Fenster starten.cmd"
nehmen - dann bleibt ein Fenster mit allen Meldungen offen.

Am Mac:  Doppelklick auf "Webserver starten.command"


BEENDEN
-------

  Doppelklick auf   "Webserver beenden.cmd"

Oder das Fenster schliessen, falls sichtbar gestartet wurde.


EIGENE SEITEN
-------------

Alles, was in den Ordner "www" kommt, ist sofort im Browser da:

  www\index.html          ->  http://localhost:8080/
  www\bilder\logo.png     ->  http://localhost:8080/bilder/logo.png
  www\shop\index.php      ->  http://localhost:8080/shop/

Liegt in einem Ordner keine "index.html" (oder "index.php"), zeigt
der Server den Ordnerinhalt als Liste an.

Beim Neuladen kommt immer der aktuelle Stand. Der Server schaltet das
Zwischenspeichern im Browser ab - beim Bearbeiten sieht man sofort,
was man geaendert hat.


EINSTELLUNGEN
-------------

Alles steht in der Datei "einstellungen.txt". Sie wird beim ersten
Start angelegt. Nach einer Aenderung den Server neu starten.

  port = 8080       Auf welchem Port der Server laeuft.
                    Bei "80" entfaellt die Portangabe in der Adresse:
                    dann genuegt  http://localhost
                    Ist der Port belegt, nimmt der Server von selbst
                    den naechsten freien.

  ordner = www      Welcher Ordner angezeigt wird.

  browser = ja      Browser beim Start oeffnen.

  netzwerk = nein   Bei "ja" koennen auch Handy, Tablet oder die
                    Kollegen im selben Netz die Seiten aufrufen.
                    Die Adresse dafuer steht dann beim Start dabei.

  ordnerliste = ja  Ordnerinhalt anzeigen, wenn keine index.html da ist.


PHP UND SQLITE
--------------

Fuer PHP wird ein PHP im Ordner gebraucht:

  1. Auf https://windows.php.net/download die Fassung
     "VS17 x64 Non Thread Safe" als ZIP herunterladen.
  2. Entpacken und den Ordner "php" nennen, direkt neben server.js.
     Es muss also "php\php-cgi.exe" geben.
  3. Server neu starten.

Beim ersten Start legt der Server dort eine "php.ini" an, in der
SQLite und die ueblichen Erweiterungen eingeschaltet sind. Eine
bereits vorhandene "php.ini" wird nie veraendert.

Ob alles laeuft, zeigt   http://localhost:8080/test.php

SQLite braucht keine Installation - die Datenbank ist einfach eine
Datei. In PHP genuegt:

  $db = new PDO("sqlite:" . __DIR__ . "/../daten/meine.sqlite");

Datenbanken gehoeren nicht in "www", sondern daneben - zum Beispiel
in einen Ordner "daten". Sicherheitshalber liefert der Server
Dateien wie .sqlite, .db und .env ohnehin nie an den Browser aus,
auch wenn sie in "www" liegen.


MEHRERE ARBEITSPLAETZE AUF EINEM SYNC-ORDNER
-------------------------------------------

Liegt der Ordner in Nextcloud und jeder startet seinen eigenen Server,
arbeiten alle auf denselben Dateien. Wer dabei einfach speichert,
ueberschreibt die Aenderungen der anderen.

Damit das nicht passiert, gibt es "www\lib\speicher.php". Datensaetze
kommen dort in eine JSON-Datei, die sich zusammenfuehren laesst:

  require __DIR__ . "/lib/speicher.php";
  $speicher = new Speicher(__DIR__ . "/../daten/kunden.json");

  $id = $speicher->sichern(["name" => "Anna Berger"]);
  $alle = $speicher->alle();
  $speicher->loeschen($id);

Jeder Datensatz bekommt eine Kennung und einen Zeitstempel. Treffen zwei
Staende aufeinander, gewinnt der juengere Datensatz - nicht die juengere
Datei. Konfliktkopien von Nextcloud werden automatisch eingemischt.

Zum Anschauen:  http://localhost:8080/beispiel.php

Zwei Dinge dazu:

  * Die Uhren der Rechner sollten stimmen. Geht einer nach, verlieren
    seine Aenderungen.
  * Bearbeiten zwei Personen gleichzeitig DENSELBEN Datensatz, setzt
    sich die spaetere Fassung ganz durch. Verschiedene Datensaetze
    gleichzeitig zu bearbeiten ist immer sicher.

Wichtig: Datenbanken und Datendateien gehoeren nach "daten", nicht nach
"www". Sonst kann sie jeder ueber den Browser herunterladen.

SQLite ist fuer einen Sync-Ordner mit mehreren Leuten NICHT geeignet -
die Datei kann dabei beschaedigt werden. Fuer einen einzelnen Arbeits-
platz ist sie voellig in Ordnung.


WAS IM ORDNER LIEGEN MUSS
-------------------------

  server.js             das Programm
  node.exe              wird zum Ausfuehren gebraucht (rund 80 MB)
  www\                  die eigenen Seiten
  php\                  nur noetig, wenn PHP verwendet wird
  einstellungen.txt     legt der Server selbst an

  Anleitung.html        die bebilderte Anleitung

  Webserver starten.vbs
  Webserver mit Fenster starten.cmd
  Webserver beenden.cmd
  Webserver starten.command      (fuer Mac)

Die "node.exe" muss NICHT installiert werden - sie liegt einfach mit
im Ordner. Fehlt sie, sagen die Startdateien, wo es sie gibt.


WENN ETWAS NICHT STIMMT
-----------------------

"Node.js wurde nicht gefunden"
  Die node.exe fehlt. Sie steckt in der ZIP-Datei
  "Windows Binary (.zip)" auf https://nodejs.org/en/download
  im Ordner "node-vXX-win-x64".

"PHP ist nicht eingerichtet"
  Der Ordner "php" fehlt - siehe oben.

Die Seite zeigt eine Ordnerliste statt der Startseite
  In dem Ordner fehlt eine "index.html".

Port 80 laesst sich nicht verwenden
  Er ist meist schon belegt, oft von IIS oder Skype.
  In "einstellungen.txt" zum Beispiel 8080 eintragen.

Aenderungen an einer Seite sind nicht zu sehen
  Der Server sendet immer den aktuellen Stand. Haelt der Browser
  etwas fest, hilft Strg+F5.
